Q13 - PARTIAL INDEX WHERE status = 'GAGAL'

Query:
EXPLAIN (ANALYZE, BUFFERS)
SELECT event_id, terjadi_pada, jumlah
FROM lab6.event_log
WHERE status = 'GAGAL'
ORDER BY terjadi_pada DESC
LIMIT 20;

CREATE INDEX ev_gagal_part_idx
ON lab6.event_log (terjadi_pada DESC)
WHERE status = 'GAGAL';

Predikat tidak cocok:
EXPLAIN (ANALYZE, BUFFERS)
SELECT event_id, terjadi_pada, jumlah
FROM lab6.event_log
WHERE status = 'TERTUNDA'

Hasil:
- Partial index tidak dipakai untuk status TERTUNDA karena predikat tidak cocok.
- Planner kembali ke scan biasa, kemungkinan Sort masih muncul.

Ukuran partial vs full index:
SELECT c.relname AS indeks,
       pg_size_pretty(pg_relation_size(c.oid)) AS ukuran,
       pg_relation_size(c.oid) AS bytes
FROM pg_index i
JOIN pg_class c ON c.oid = i.indexrelid
WHERE i.indrelid = 'lab6.event_log'::regclass
ORDER BY c.relname;

Penjelasan:
- Partial index cocok untuk query status='GAGAL' karena hanya mencakup subset data.
- Jika query memakai status lain, planner tidak memakai index.
- Ukuran partial index biasanya lebih kecil daripada full index pada (status, terjadi_pada).
